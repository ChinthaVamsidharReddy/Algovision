## Hard rules
1. **Use only the existing state kinds.** Do NOT modify `packages/trace-schema`, `packages/viz-engine`, `apps/`, `tools/`, `catalog.json`, `registry.ts`, `index.ts`, `src/generated/`, or any file outside your own algorithms. If an algorithm cannot be expressed with the existing kinds, skip it and say why in your report. Never change a major technical decision.
2. Input kinds are `intList`, `int` and `text` (lowercase a-z; see `src/content-types.ts`). A `text` input is a string in `vectors.json` and is sent to the language harnesses as "n c1 .. cn" character codes (see `sharness` in the scratch generators). For any other data, encode it as integers and say so in the input `label`/`note` (e.g. 1=`(`, 2=`)`).
3. **Every algorithm must have verified Java, Python, C++ and C solutions** with `@a <anchor>` markers, harnesses, vectors, executor, and tests. Anchors declared in `algorithm.json` must all appear in every language and every anchor the executor emits must be declared and be reachable by the default/vector inputs.
4. Vectors must be produced by an **independent reference** (write a small Python script, run it, paste/write the JSON), not by the executor under test. Include: empty (if the input is accepted), single, boundary/limit values (±999 where applicable), duplicates/negatives where meaningful, and ≥5 seeded random cases.
5. Every explanation sentence must be non-empty plain English for a learner; trace results must validate with `validateTrace`; step counts must fit the `standard` limits for the maximum input (and the `lite` profile for the default input). Check worst-case step counts and pick the input limits accordingly (reject over-large inputs with a clear message rather than exceed `maxSteps`).
6. Shared build: the content compiler (`pnpm build:content`) reads **every** directory under `content/` and fails if any is incomplete. Other agents are working in parallel. So: author each algorithm in `packages/algorithms/.staging/<id>/` (same layout as `content/<id>/`), and **move it into `content/<id>/` only when all 11 files are complete** (`mv`). If `pnpm build:content` fails because of someone else's directory, wait ~30 s and retry; never edit or delete another agent's files.
7. Registration: put the executor in `src/algorithms/<id>.ts`, and register it **only** by editing your own barrel `src/algorithms/wave<LETTER>.ts` (add an import and add the definition to the array). Do not touch any other shared file.
8. Tests: write `test/wave<LETTER>-algorithms.test.ts`. Run `cd packages/algorithms && pnpm build:content && REQUIRE_TOOLCHAINS=1 npx vitest run test/wave<LETTER>-algorithms.test.ts test/content.test.ts test/conformance.test.ts`. Also run `npx tsc -p tsconfig.json && npx tsc -p tsconfig.test.json` and `npx eslint packages/algorithms` from the repo root (lint must be clean; use `!==`/`===`).
